# Pitch sparring partner

Practise a pitch in front of an AI panel that listens, reacts with micro-expressions, asks you hard questions out loud, and then gives you a report and the full recording.

Built at the Imperial College AI Hack (Voice, Vision and Generative Media track).

## The problem

Most people practise pitches alone, to a wall. You get no reaction while you speak, no awkward follow-up question and no honest account of how you came across. Coaching is expensive, and friends are too kind.

## What we built

1. **Setup.** Choose a panel (sceptical investors, friendly peers, interview panel or a custom one), upload your slides as a PDF, set the pitch length and the number of questions, and optionally paste context such as judging criteria or a job description.
2. **Solo pitch.** Your slides are the main stage. The panel listens silently and reacts with micro-expressions: a nod when you land a point, a sceptical look when you make a claim without evidence, a glance away when you drone. Each persona reacts differently to the same moment. The whole session is recorded in the browser.
3. **Q&A.** The panelists ask questions aloud, one at a time, as talking avatars. Each question is grounded in what you said and what your slides show. While you answer, the agent can call tools to check your transcript, a slide or your delivery metrics, and it follows up if your answer is vague.
4. **Report.** You get an overall score with its component scores, your best 20 seconds, one to three priorities, delivery timelines by slide, content feedback per rubric dimension, feedback on each answer, and the full recording with clickable markers.

## How it works

```
Browser (React + Vite)                                    Server (Node + Express)
───────────────────────────────────────────────           ─────────────────────────────────────
PDF.js ── slide images + per-slide text                   /api/voice/scribe-token  → ElevenLabs single-use token
MediaRecorder ── camera+mic recording, audio-only copy    /api/voice/transcribe    → ElevenLabs Scribe (word timestamps)
MediaPipe face + hand landmarks ── eye contact, gestures  /api/voice/anam-session  → ElevenLabs signed URL → Anam session token
Web Audio ── loudness + pitch (tonality)                  /api/voice/signed-url    → voice-only fallback
ElevenLabs Scribe realtime ── live transcript             /api/llm/questions       → Claude, structured output
          │                                               /api/llm/evaluate        → Claude, structured output (zod)
          ▼                                               /api/media/*             → fal images + image-to-video clips
   one timestamped event stream                           /api/sessions            → session JSON + recording on disk
   (filler_burst, long_pause, fast_pace, monotone_stretch,
    eye_contact_lost, strong_moment, claim_without_evidence,
    slide_changed, …)
          │
          ├── audience reactions during the pitch (per-persona expression profiles)
          └── report: delivery layer (measured) + content layer (Claude) → overall
```

**Voice and avatars.** One ElevenLabs Conversational AI agent plays every panelist. Each persona is injected per session through dynamic variables (name, role, personality, focus, strictness and the planned question), and the voice is overridden per persona. In Q&A, Anam renders the panelist as a talking avatar. Anam's engine connects to the ElevenLabs agent server-side, so the agent's voice drives the avatar's face. The agent's client tools (`get_transcript`, `get_slide`, `get_metrics_summary`, `log_answer_assessment`, `end_qna`) run in the browser through Anam's `registerToolCallHandler`. If Anam is unavailable, the same agent runs voice-only. If that fails too, the browser reads the questions aloud. The demo never stalls.

**Reactions during the pitch.** Anam expression cues only apply while an avatar is speaking. During the silent pitch, each panelist is therefore a fal-generated portrait with short reaction clips (nod, smile, frown, glance away, sceptical look) generated by fal image-to-video from that portrait. Without clips, the portrait plays a subtle CSS motion instead.

**Evaluation.** Delivery signals (pace, fillers, deliberate versus hesitant pauses, eye contact, gestures and tonality) are measured locally. Each signal is hidden rather than shown when it is unreliable. Claude scores the content against a rubric: overall pitch, clarity, depth of thinking, Q&A performance and composure. Each score comes with a justification that points to a moment in the recording. The output is validated against a schema on both the server and the client. The overall score is `CONTENT_WEIGHT × content + (1 − CONTENT_WEIGHT) × delivery`. `CONTENT_WEIGHT` is 0.65 by default and lives in [web/src/lib/metrics.ts](web/src/lib/metrics.ts). The report always shows the component scores.

**Privacy.** Video is analysed in the browser with MediaPipe and is never uploaded for analysis. The recording is stored only on your own server, for playback.

## Running it

Requirements: Node 20 or later and Chrome.

```bash
npm run setup                 # installs server and web, downloads MediaPipe models for offline use
cp .env.example .env          # add your keys (each one is optional; missing ones use a fallback)
npm run create-agent          # creates the ElevenLabs panelist agent; paste the printed ELEVENLABS_AGENT_ID into .env
npm run dev:server            # terminal 1, http://localhost:8787
npm run dev:web               # terminal 2, open http://localhost:5173
```

For Anam you need a Cara 4 avatar id in `ANAM_AVATAR_ID`, or one per seat in `ANAM_AVATAR_IDS`. Before the demo, open the setup screen and click **Generate room and portraits**, then **Animate reactions** (this takes a few minutes). Generated media is cached in `server/data/generated` and reused.

What works without which key:

| Missing key | Effect |
| --- | --- |
| `ELEVENLABS_API_KEY` | No transcript, so pace, fillers and pauses cannot be measured; questions read by the browser |
| `ELEVENLABS_AGENT_ID` | Questions read by the browser instead of the voice agent |
| `ANAM_API_KEY` / avatar id | Voice-only panel during Q&A |
| `ANTHROPIC_API_KEY` | General questions; report uses delivery only |
| `FAL_KEY` | Initials instead of portraits, plain backdrop, CSS reactions |

**Demo backup.** Every session is saved with its recording. Past sessions are listed on the setup screen and open at `/#/report/<id>`, so a good earlier run can be shown if the network fails.

## How it qualifies for each prize

- **Best ElevenLabs project.** A real-time voice agent with agentic depth: per-persona dynamic variables and voices, five client tools it calls mid-conversation to fact-check the speaker against the transcript and slides, follow-up logic, and self-ending turns. ElevenLabs Scribe also powers the live transcript (realtime) and the accurate word-timestamped transcript (batch) that drive the delivery metrics.
- **Best use of Anam.** Panelists are Anam avatars driven by the ElevenLabs agent, with tool calls handled through Anam's tool-call handlers. Director Notes give each persona its own idle listening style and expressivity.
- **Best use of fal.** fal generates the audience environment per panel type, a portrait for every panelist (including custom ones), and image-to-video reaction clips that give silent panelists visible micro-expressions during the pitch.
- **Best-designed AI product.** One primary action per screen, a small set of neutral colours with one accent, sentence-case copy, glanceable low-key metrics during the pitch, light and dark mode, and helpful empty and error states throughout.

## APIs, models and libraries

- **ElevenLabs:** Conversational AI agents (agent LLM `claude-haiku-5-5`, TTS `eleven_v4_turbo`), Scribe v2 realtime (`scribe_v2_realtime`), Scribe v2 batch speech to text (`scribe_v2`), premade voices. SDKs `@elevenlabs/client`, `@elevenlabs/elevenlabs-js`.
- **Anam:** avatar streaming with the ElevenLabs server-side integration, Cara 4 avatars, `@anam-ai/js-sdk`.
- **fal:** `fal-ai/flux/schnell` (images), `bytedance/seedance-2.0/fast/image-to-video` (reaction clips), `@fal-ai/client`.
- **Anthropic:** Claude (`claude-opus-5-5` by default) for questions and content evaluation, with structured outputs. `@anthropic-ai/sdk`.
- **Google MediaPipe Tasks Vision:** Face Landmarker and Hand Landmarker models, `@mediapipe/tasks-vision`.
- **Mozilla PDF.js:** `pdfjs-dist`.
- **Other libraries:** React, Vite, TypeScript, Express, multer, zod, dotenv, tsx.
- **Datasets:** none.

All project code was written during the hackathon.
